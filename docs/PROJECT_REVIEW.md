# 프로젝트 구조 및 버그 점검

점검일: 2026-10-08. 후속 수정: 2026-10-09. 기존 작업 중인 변경을 유지하면서 실행 로직과 상태 갱신을 정리했다. 게임 콘텐츠, 구매 가격, 생산량, 기존 콘텐츠의 해금 순서는 변경하지 않았다.

## 구조

현재 규모에는 아래 역할 분리가 적절하다. 디렉터리를 재배치하기보다 각 계층 사이의 상태 변경 알림을 보완했다.

| 위치 | 책임 |
| --- | --- |
| `autoload/EconomyManager.gd` | 자금과 전체 수입·시간 배율 |
| `autoload/IncomeManager.gd` | 수입원 활성 상태, 레벨, 생산 진행 및 지급 |
| `autoload/ButtonManager.gd` | 구매 가능 여부, 결제, 효과 적용, 해금 상태 |
| `autoload/PrestigeManager.gd` | 환생 보상과 초기화 순서 |
| `autoload/ErrorManager.gd` | 공통 검증, 오류 메시지 표시, 중복 알림 방지 및 오류 이력 |
| `data/`, `scripts/ResourceInit/` | 콘텐츠 정의와 리소스 형식 |
| `scenes/world_layout.tscn` | 월드 배치와 렌더링 깊이 |
| `scenes/main.gd`, `ui/` | 장면 조립, 입력, 화면 표시 |

## 수정한 문제

- **환생 후 화면 잔류:** 구매 상태는 초기화돼도 해금 여부가 계속 `false`인 버튼은 갱신 신호가 없었다. 모든 버튼에 초기화 알림을 보내 구매 그림과 클릭 영역을 갱신하도록 수정했다. 수입원 초기화도 활성 상태·타이머·레벨 변경을 알린다.
- **업그레이드 목록 중복:** `queue_free()`만 호출하면 같은 프레임의 재구성에서 이전 행이 남았다. 부모에서 즉시 분리하고 삭제를 예약하며, 재구성 때 누르고 있던 업그레이드도 중지한다. 수입 변화에 대한 구독을 통합했다.
- **환생 중 말풍선 잔류:** 프레임 대기 중이던 말풍선이 초기화 뒤에도 꼬리와 타이머를 다시 켰다. 초기화 때 말풍선을 숨기고, 대기 이후 구매 상태를 재확인한다.
- **결제 신호에 의한 중복 구매:** 결제 도중 `money_changed`의 구독자가 같은 구매를 요청하면 두 번 차감하고 효과도 두 번 적용할 수 있었다. 진행 중인 구매에 대한 재진입을 차단했다.
- **효과 없는 결제:** 존재하지 않는 수입원이나 적용 불가능한 배율 효과를 구매할 수 있었다. 효과 대상과 배율 곱의 유효성을 결제 전에 확인한다.
- **초고속 생산의 정수 범위 초과:** 완료 회차를 `floori()`로 변환하던 부분을 부동소수점 회차 계산으로 바꾸고, 남은 시간은 나머지 연산으로 보존한다. 일반적인 생산, 긴 프레임, 속도 변경 시 진행률 유지도 검증했다.
- **자금·배율의 무한대 오염:** 입력 각각이 유한해도 덧셈·곱셈 결과가 무한대일 수 있었다. 유효하지 않은 결과가 기존 상태를 덮어쓰지 않게 했다. 이는 큰 수 지원의 대체 수단은 아니다.
- **숫자 표시 오류:** `999.999`가 `999.00`으로 표시되는 자리올림 오류를 수정했다. 0.01 미만의 양수는 과학적 표기로 표시하여 빠른 생산 시간이 0초로 보이지 않게 했다.
- **화면 갱신 및 위치:** 전체 수입 배율 변경이 수입 화면에도 전달되게 했다. 월드 배치 부모의 위치·크기가 변경되면 생산 타이머와 카메라 가로 범위가 어긋나는 문제를 수정했다. 구매 UI와 말풍선도 부모 좌표계를 고려한다.
- **구매 애니메이션 중첩:** 애니메이션이 끝나기 전에 다시 재생하면 중간 크기나 0을 원래 크기로 저장할 수 있었다. 이전 애니메이션을 중지하고 최초 크기로 복원한다.

## 남아 있는 위험

### 1. 큰 수의 정확도와 표현 범위 — 높음

`EconomyManager.money`, 배율, 가격, 생산량은 [정밀도에 한계가 있는 Godot의 `float`](https://docs.godotengine.org/en/stable/classes/class_float.html)이다. 최초 점검에서는 자금 `1e20`원일 때 `spend_money(1.0)`이 성공해도 잔액은 바뀌지 않았다. 후속 수정에서는 증감이 완전히 사라지는 경우 `PRECISION_LOSS`를 표시하고 실패를 반환한다. 유효하지 않은 수치 결과도 표시하고 거절한다. 한도를 넘는 수입을 저장하는 문제, 부분적으로 반올림되는 정밀도 손실, 지수형 업그레이드 가격과 여러 배율을 곱한 최종 생산량의 표현 범위는 남아 있다.

큰 수를 계속 키우는 게임 설계를 유지하려면 자금·가격·생산량·배율을 함께 다루는 가수/지수 또는 임의 정밀도 수치 형식이 필요하다. 표시만 과학적 표기로 바꾸면 계산 정확도는 해결되지 않는다.

### 2. 환생 보상의 정수 범위 초과 — 높음

`PrestigeManager.get_current_jjam()`의 `floori()`와 `total_jjam: int`에는 별도의 정수 한계가 있다. 최초 점검에서는 자금 `1e45`원의 환생 보상이 조용히 0으로 계산되었다. 후속 수정에서는 변환 전 보상 범위와 누적 덧셈 범위를 검사하며, `JJAM_OVERFLOW`를 표시하고 자금·구매 상태를 유지한 채 환생을 중단한다. 표현 범위를 넘는 보상을 실제로 저장하려면 여전히 큰 수 형식이 필요하다.

### 3. 문자열 ID와 수동 등록의 결합 — 중간

버튼 ID, 효과 대상, 해금 조건의 `value`, 월드 노드 이름이 문자열로 연결된다. `ButtonManager.buttons`와 `IncomeManager.sources`에도 각각 등록해야 한다. 중복 ID는 검색 결과와 런타임 딕셔너리 상태를 다르게 만들 수 있고, 월드 노드 이름이 틀리면 구매 로직이 존재해도 화면 구성에서 빠질 수 있다. 순환 해금 조건은 진행을 막는다.

후속 수정으로 `ErrorManager`가 시작 시 등록 목록·참조·해금 순환을 검사한다. 실행 중 조회에서도 누락·중복 ID를 알리고 임의의 항목을 반환하지 않는다. 월드 노드 이름의 중복·누락과 이미지·클릭 영역 문제도 감지하며 해당 버튼의 구매를 차단한다. 잘못된 필수 UI 노드는 해당 화면의 동작을 중단한다. 현재 콘텐츠의 전체 구매 경로와 의도적으로 잘못된 구성을 넣은 검증이 통과했다.

### 4. 미처리 해금 조건 — 해결

`UPGRADE`를 `TOTAL_JJAM`으로 교체했다. `amount`에 필요한 누적 짬을 지정하며, `PrestigeManager.total_jjam`을 기준으로 판단한다. 예상 환생 보상은 포함하지 않는다. 환생 완료 때 해금 상태를 다시 계산하며, 잘못된 조건 종류나 소수 짬 기준은 오류를 표시하고 거절한다.

### 5. 개발자 도구의 배포 노출 — 수정 완료

`main.gd`의 O 키 처리에 `OS.is_debug_build()` 검사를 추가했다. 개발자 도구는 디버그 빌드에서만 O 키로 열 수 있으며, 출시 빌드에서는 해당 키 입력을 처리하지 않는다.

### 6. 배치 정보 중복 — 낮음

`IncomeSourceData.display_position`과 `display_scale`은 리소스에 남아 있지만 실제 생성 위치는 `world_layout.tscn`에서 읽는다. 리소스의 이 값을 수정해도 월드 배치는 바뀌지 않는다. 현재는 월드 장면을 배치의 기준으로 사용해야 한다. 기존 리소스의 호환성을 유지하기 위해 필드를 삭제하지 않았다.

## 검증

이 점검 당시에는 Godot 4.7.2에서 계산·구매·환생 UI, 렌더링 깊이, 잘못된 데이터와 오류 표시를 세 회귀 테스트로 검증했다. 이후 기존 테스트는 모두 삭제하고 최저가 구매 밸런스 테스트로 교체했다. 현재 실행 명령은 다음과 같다.

```text
godot --headless --path . --fixed-fps 60 res://tests/balance_playthrough.tscn
```

현재 테스트는 해금된 버튼과 활성 수입원의 레벨업 중 가장 싼 항목을 선택해 실제 게임의 생산과 구매를 진행한다. 버튼별 가격과 구매 시간, 전체 구매 경로는 `res://logs/balance_playthrough.txt`에 저장한다. 기존 회귀 테스트의 모든 검증 범위를 포함하지는 않는다. 실제 모바일 터치 입력과 출시용 내보내기는 이 점검에 포함하지 않았다.

오류 객체의 책임과 사용법은 README의 오류 처리 항목을 참고한다. 게임 시작 전의 문법 오류·필수 `preload` 실패 등 엔진 오류 전체를 가로채는 객체는 아니다.
