# 짬 환생

- `PrestigeManager.jjam_unlocked`: 슬롯별 영구 해금. 첫 짬통 구매 시 켜지며 짬 환생으로 꺼지지 않습니다.
- `banked_jjam`: 환생으로 확정한 짬. 수입 부스트의 기준입니다.
- `live_jjam` / `current_jjam`: 이번 환생에서 받을 짬. 부스트나 재화 소비에는 사용하지 않습니다.
- `total_jjam`: 확정 짬 + 실시간 짬.
- `prestige_count`: 새 짬 환생의 실행 횟수. `No Prestige Only` 이벤트는 이 값으로 판별합니다.

## 계산과 저장

`IncomeManager.total_earned_income`은 전체 누적 수익이고, `jjam_earned_income`은 첫 해금 이후 이번 환생까지의 수익입니다. 지출과 별도로 보관하며 큰 수의 잔여 정밀도도 저장합니다. 수입원 지급, 수락한 폰 DM 보상, 개발자 도구로 추가한 금액을 모두 수익으로 계산합니다. 짬통 해금 이후 개발자 도구로 추가하는 금액도 같은 환산 비율로 실시간 짬에 즉시 반영됩니다. 폰 DM 보상은 거래 확정 때 한 번만 기록하므로 입금 애니메이션 중 저장해도 중복 계산되지 않습니다.

첫 해금부터 첫 환생까지는 400짬을 추가하며, 초기 `money_per_jjam`은 **120억 원(12,000,000,000원)**, `boost_per_jjam`은 1%입니다. 두 값은 `autoload/PrestigeManager.gd`의 export 변수입니다. 획득 난이도 계수는 **`data/balance/jjam_growth.tres`의 `difficulty_multiplier`**로 조정합니다. 현재 `.tres` 설정인 **2.5**를 유지하며 리소스 스크립트의 기본값은 4.0입니다.

획득 난이도는 **이번 회차의 실시간 짬만** 기준으로 합니다. 확정 짬은 획득 비용을 높이지 않습니다. `n = max(0, floor(log2(max(실시간 짬, 400) / 400)))`일 때 해당 구간에서 1짬의 필요 수익은 `money_per_jjam × difficulty_multiplier^n`입니다. 현재 계수 2.5에서 실시간 짬 800 미만은 120억 원, 800~1,599짬은 300억 원, 1,600~3,199짬은 750억 원, 3,200~6,399짬은 1,875억 원당 1짬입니다. 실시간 짬이 2배인 구간으로 넘어갈 때마다 비용에 계수를 곱하며, 계수 1이면 선형 환산으로 돌아갑니다.

큰 수익은 지나는 구간별 비용을 순서대로 적용합니다. 상점에서 확정 짬을 써도 획득 곡선과 이미 얻은 실시간 짬은 바뀌지 않습니다. 환생에서는 실시간 짬과 해당 회차의 수익을 초기화하므로 획득 비용이 초기 구간으로 돌아갑니다. 확정 짬의 수입 보너스가 유지되어 같은 수입원을 같은 시간 가동해도 새 회차 초반에는 더 빠르게 짬이 쌓입니다. 첫 해금의 400짬은 처음 한 번만 주며 이후 환생에서는 실시간 짬 0부터 시작합니다. 1짬 미만의 진행분을 유지하고 최종 표시·사용 가능한 짬만 버림합니다.

수입 배율은 `1 + banked_jjam × boost_per_jjam / 100`입니다. 새 짬 환생을 한 번도 하지 않았다면 0% 보너스입니다. `jjam_system_version = 1` 또는 2인 저장은 확정 짬·상점 구매·첫 지급 여부를 유지하고 실시간 짬만 현재 회차의 수익으로 재계산합니다. 저장 버전은 2를 유지하며 이전 `growth_spending` 기록은 계산에서 제외하고 새 저장에는 빈 배열로 둡니다. 그보다 오래된 버전 필드가 없는 저장의 짬은 기존 이관 규칙에 따라 폐기하고 전역 배율에 포함된 옛 짬 배율을 제거합니다.

`res://tests/jjam_growth.tscn`에서 실시간 짬만 따르는 구간 경계, 초기 환산 비율, 조절 가능한 계수, 한 번에 여러 구간을 넘는 수익, 상점 지출 독립성, 소수 진행분, 반복 환생의 초기 비용 복원, 같은 수입원의 환생 전후 짬 획득 가속, 저장 이관, 예약 수익 취소와 큰 수 계산을 검증합니다. 경계 검사는 계수 4의 복제 리소스를 사용하므로 사용자가 조정한 `.tres` 설정은 변경하지 않습니다.

## UI와 이벤트

### 짬 상점

패널은 저장·우측 진입 버튼을 피한 가용 영역까지 커지며 최대 크기는 1600×1000입니다. 환생 내용은 가로·세로 화면에 맞게 배치하고 전체 크기를 조정해 한 화면에 표시합니다. 환생 내용과 확인창에는 스크롤을 사용하지 않으며, 상점의 상품 목록만 스크롤할 수 있습니다.

짬 환생 패널 위쪽의 환생 / 상점 탭으로 전환합니다. 상품 정의는 `scripts/ResourceInit/JjamShopItemData.gd`이며 `data/jjam_shop/`의 `.tres` 리소스를 `PrestigeManager.shop_items`에 등록합니다. `id`, 이름, 아이콘(`icon`), 설명, 짬 가격, `feature_id`를 설정할 수 있습니다. 기본 가격은 정수 `price`이며, `large_price`(Inspector의 Large Price)에 `25e16` 또는 `1.25e500` 같은 문자열을 입력하면 `get_price()`가 큰 수로 해석하여 기본 가격을 덮어씁니다. 비어 있거나 공백뿐이면 `price`를 사용합니다. 표시·구매 조건·결제·가격 숨김·확인창은 모두 이 유효 가격을 사용합니다. 아이콘은 상품명 왼쪽에 원래 비율을 유지해 표시합니다. 수입원 업그레이드 패널 상품은 우측 진입 버튼과 같은 `Button_UI_Upgrade.png`를 사용합니다.

상품은 확정된 `banked_jjam`만 사용해 한 번 구매합니다. 구매 이력은 슬롯별로 저장하고 짬 환생 후에도 유지합니다. 지출만큼 확정 짬과 그에 따른 수입 부스트가 감소하며 실시간 짬은 사용하지 않습니다. 구매 확인창에서 가격이 현재 짬의 절반을 초과하면 빨간색 경고를 표시합니다.

각 상품 설명 오른쪽에는 `Button_buy_Blue.png` 구매 버튼을 표시하고 가격은 버튼 아래에 둡니다. 구매를 마친 상품은 가격 자리를 「구매 완료」로 바꾸고, 구매 불가 상태의 버튼은 어둡게 표시합니다.

미구매 상품은 `(banked_jjam + live_jjam) × 10000 < price`이면 가격을 `???짬`으로 표시합니다. 가격 위에 마우스를 올리면 `TooltipManager`가 「감히 넘볼 수 없는 짬입니다...」를 표시합니다. `PrestigeManager.is_shop_price_distant()`에서 모든 상품에 동일한 규칙을 적용하며 큰 수와 실시간 짬도 반영합니다. 툴팁은 가격을 벗어나거나 스크롤·탭 전환·패널 닫기 시 사라집니다.

첫 상품 `batch_upgrade_panel.tres`는 100짬으로 수입원 업그레이드 패널을 해금합니다. 상품 ID와 기능 ID는 `batch_upgrade_panel`이며, 이전 `income_upgrade_panel`로 저장된 구매 이력도 불러올 때 유지됩니다. 구매 전에는 우측 패널 버튼이 잠겨 있습니다. 수입원 자체에는 타이머 위의 레벨과 아래의 개별 업그레이드 버튼·가격이 표시됩니다. 개별 버튼은 기존 원화 업그레이드 가격과 레벨 계산을 공유합니다.

일괄 업그레이드 패널의 씬은 `res://ui/batch_upgrade_panel.tscn`, 스크립트와 클래스는 `BatchUpgradePanel.gd` / `BatchUpgradePanel`입니다. 메인 씬에서는 `RightPanel/BatchUpgradePanel`에 배치됩니다.

`bulk_upgrade_5.tres`의 「5레벨씩 업그레이드」는 400짬입니다. 구매 즉시 +5 모드를 적용하고 같은 카드의 상품명·아이콘·설명·구매 대상을 「25레벨씩 업그레이드」(`bulk_upgrade_25.tres`, `large_price = "25e16"`, 25경짬)로 바꿉니다. 현재 모드 전환 버튼은 BUY 왼쪽에 추가되며, 그 위에 「클릭하여 모드 전환」을 작게 표시합니다. +25 구매 전에는 +1 / +5, 구매 후에는 +1 / +5 / +25 순서로 전환합니다. +25를 구매하면 즉시 +25 모드를 적용합니다. 단계 연결은 상품 리소스의 `prerequisite_item_id`와 `next_item_id`, 업그레이드 단위는 `upgrade_levels`로 설정합니다.

구매 이력과 선택 모드는 슬롯별로 저장하고 환생 후에도 유지합니다. 모드 구매 후에만 개별·일괄 업그레이드 버튼 오른쪽 위에 `plus_1.png`, `plus_5.png`, `plus_25.png` 중 현재 모드의 배지를 표시합니다. 여러 레벨의 비용은 각 레벨의 반올림된 가격을 합산하며, 전액이 있어야 선택한 레벨 수를 한 번에 올립니다. 수입 미리보기도 선택한 레벨 수를 반영하고 효과음은 도착 레벨을 기준으로 진행합니다.

### 연출과 패널

`data/events/jjamtong_intro_event.tres`는 짬통 구매 조건의 Instant / One Off 이벤트입니다. `JjamPrestigePresentation`이 UI와 입력을 잠그고 카메라 이동, 기존 고양이 빼꼼 애니메이션, 1초 대기, 원래 줌 복귀를 처리합니다. 슬롯을 바꾸면 진행 중인 연출을 취소하고 입력과 UI를 복구합니다.

새 우측 패널은 `RightPanelManager.register_panel(content)`로 등록하고 `open_panel(content)` 또는 `toggle_panel(content)`로 엽니다. 다른 등록 패널은 자동으로 닫힙니다. 저장 화면은 `close_all()`을 호출하고 개발자 도구는 이 관리자에 등록하지 않습니다.

표시 순서: 기본 HUD → 우측 버튼 → 저장 화면 → 이벤트 → 환생 암전 → 개발자 도구 → 오류 화면.

짬 환생은 암전 중 확정 짬 추가, 실시간 수익 초기화, 돈·일반 구매·수입원 레벨과 배율 초기화, 카메라 복귀를 처리하고 패널을 닫습니다. 우측 짬 환생 버튼, 영구 해금, 일회성 이벤트 이력은 유지합니다. 재입대·초월 로직은 아직 구현하지 않습니다.

화면이 밝아지면 `data/effects/jjam_prestige_cats.tres`의 설정으로 고양이 30개가 0.3초에 걸쳐 화면 곳곳에서 나타납니다. 각 고양이는 짧게 튀어나온 뒤 1초 동안 우측 짬 환생 버튼으로 모이며 작아집니다. 재사용 장면은 `ui/effects/jjam_cat_effect.tscn`입니다. 화면 크기가 바뀌어도 도착점은 현재 버튼 중앙을 따라가며, 슬롯을 바꾸면 남은 이펙트를 정리합니다.
