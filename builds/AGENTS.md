# 빌드 및 배포 지침

이 폴더에서 빌드·패키징·릴리즈를 준비할 때 다음 규칙을 적용한다. 사용자의 요청에 따라 앞으로 만드는 빌드의 한국어 이름은 **우정회관 키우기**로 통일한다.

## 앱 표시 이름과 파일 이름

- Windows 실행 파일 이름: `우정회관 키우기.exe`
- 별도 Godot 데이터 팩이 있으면 이름: `우정회관 키우기.pck`. 실행 파일과 같은 폴더에 함께 배포한다.
- Android 설치 파일 이름: `우정회관 키우기.apk`
- 앱 설치 후 런처에 보이는 이름, 게임 창 제목, Windows 제품 이름·파일 설명도 `우정회관 키우기`를 사용한다.
- 이름의 한글과 띄어쓰기를 그대로 유지한다. 실행 파일 이름에 영문 프로젝트명이나 버전 접미사를 붙이지 않는다. 버전과 플랫폼은 상위 폴더 또는 배포 ZIP 이름으로 구분한다.
- 배포 ZIP도 한글 게임 이름으로 시작한다. 예: `우정회관 키우기-prealpha-v1.5-windows-x86_64.zip`, `우정회관 키우기-prealpha-v1.5-android.zip`.

## 빌드·패키징에 반영할 사항

- 기존 빌드 스크립트를 재사용할 때도 출력 경로, 내보내기 설정, 압축 대상, 실행 검증 경로를 위 이름에 맞춘다. 최종 파일만 수동으로 바꾸고 스크립트에 이전 이름을 남겨 두지 않는다.
- 이름 변경에 맞춰 README, 설치 안내, 릴리즈 노트, 체크섬 목록의 파일 이름을 갱신한다. 체크섬은 최종 파일 이름과 패키징이 확정된 뒤 생성한다.
- Android 공유용 ZIP에는 APK와 게임·Godot·포함 라이브러리의 라이선스 고지를 함께 넣는다.
- Android 패키지 ID, 서명 키 등 앱의 기존 식별 정보는 이름 현지화를 이유로 변경하지 않는다. 표시 이름 변경으로 사용자 저장 경로가 바뀌는 경우에도 기존 저장 데이터를 유지하도록 경로 고정 또는 마이그레이션을 적용한다.
- 한글 및 공백이 있는 경로를 인수로 전달할 때 올바르게 인용하고, 최종 패키지의 내부 파일 이름과 실행·설치 안내가 일치하는지 확인한다.

이 지침은 향후 빌드에 적용한다. 기존에 만든 배포 파일은 별도의 요청이 있을 때 갱신한다.
